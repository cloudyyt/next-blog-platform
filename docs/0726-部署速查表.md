## 常见报错速查

### 🔴 1. scp 上传失败：`Permission denied`

**原因**：SSH 密钥未配置 / 密码错误 / 宝塔防火墙

**解决**：
```bash
# 先确认能 ssh 上去
ssh root@<服务器IP>
# 如果提示密码，输入新密码（改过的那个）
# 如果连不上：
#   - 宝塔 → 安全 → 放行 22 端口
#   - 阿里云控制台 → 安全组 → 放行 22 端口
```

---

### 🔴 2. 服务器 `pnpm: command not found`

**原因**：服务器没装 pnpm

**解决**：
```bash
npm install -g pnpm
# 或用淘宝源加速
npm install -g pnpm --registry=https://registry.npmmirror.com
```

---

### 🔴 3. 服务器 `pnpm install` 卡死 / 内存不足

**原因**：2C2G 服务器装依赖吃力

**解决**：
```bash
# 加内存 swap（临时缓解）
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile

# 或降低 pnpm 并发
pnpm install --prod --frozen-lockfile --network-concurrency 1
```

---

### 🔴 4. `migrate deploy` 报 `P3005: database schema is not empty`

**原因**：服务器 DB 是 drift 状态（早期用 `db push` 建的，无迁移历史表）

**解决**（脚本已自动处理，但若仍失败，手动跑）：
```bash
cd <SERVER_DIR>
npx prisma migrate resolve --applied 20251230174814_init
npx prisma migrate resolve --applied 20260413205000_add_post_view_tracking
npx prisma migrate deploy
npx prisma generate
```

---

### 🔴 5. `migrate deploy` 报 `P3008: Migration ... already applied`

**原因**：DB 里已有部分表但迁移历史不全

**解决**：同上，先 `migrate resolve --applied` 标记旧迁移，再 deploy

---

### 🔴 6. `seed-guide` 报 `请先执行 pnpm db:seed（建管理员）`

**原因**：服务器 DB 还没建 admin 用户

**解决**：
```bash
# 先跑基础 seed（建管理员、分类等基础数据）
pnpm db:seed
# 再跑 guide seed
pnpm db:seed:guide
```
⚠️ 但 `db:seed` 可能会重置线上数据！**先看 `prisma/seed.ts` 内容**，如果是 upsert（幂等）就安全，如果会覆盖就别跑——改用 admin 后台手动建管理员。

---

### 🔴 7. `seed-guide` 报找不到 `docs/agent-guide/manifest`

**原因**：打包时没带 `docs/agent-guide/` 目录

**解决**：本地重新打包，确认 tar 命令含 `docs/agent-guide`：
```bash
# 检查 deploy.local.sh 的打包命令
grep "tar -czf" scripts/deploy.local.sh
# 应该看到：tar -czf release.tgz .next package.json pnpm-lock.yaml prisma docs/agent-guide
```

---

### 🔴 8. pm2 restart 后网站打不开

**排查步骤**：
```bash
# 看日志
pm2 logs <PM2_NAME> --lines 50

# 常见原因：
# A. .env 的 DB 连不上 → 日志会有 "connection refused" / "ECONNREFUSED"
# B. 端口被占 → 日志会有 "EADDRINUSE"
# C. prisma client 没生成 → 日志会有 "@prisma/client not found"
#    解决：cd <SERVER_DIR> && npx prisma generate && pm2 restart <PM2_NAME>
```

---

### 🔴 9. 网站打开但数据库连接失败（500 错误）

**原因**：`.env` 的 `PRISMA_DATABASE_URL` 指错了

**排查**：
```bash
# 服务器上确认 postgres 在跑
docker ps | grep postgres       # 宝塔通常用 Docker
# 或
systemctl status postgresql

# 确认能连上
psql -h 127.0.0.1 -U <用户名> -d blog_platform
# 输入密码，能进就说明 DB 正常，问题在 .env 配置

# 检查 .env 里的连接串（注意：宝塔 postgres 端口可能不是默认 5432）
cat .env | grep PRISMA_DATABASE_URL
```

**宝塔特殊坑**：宝塔装的 postgres 端口可能改过（不是 5432），在宝塔 → 数据库 → PostgreSQL 里看实际端口。

---

### 🔴 10. 图片上传失败（OSS 相关）

**排查**：
```bash
# 看上传接口的报错
curl -X POST http://localhost:3000/api/admin/upload \
  -H "Authorization: Bearer <token>" \
  -F "file=@test.png" -F "folder=content"
# 看返回的 message

# 常见：
# A. "OSS 环境变量缺失" → .env 没配 OSS_*
# B. "OSS 权限或密钥错误" → AccessKey 填错或 RAM 权限没配
# C. 上传成功但图片不显示 → Bucket 不是公共读 / OSS 域名没加到 next.config remotePatterns
```

---

### 🟡 11. Agent 指南页面 404

**原因**：seed 没灌进去 / 章节未 published

**排查**：
```bash
# 服务器查表
psql -h 127.0.0.1 -U <用户> -d blog_platform -c \
  "SELECT slug, published, comingSoon FROM guide_chapters WHERE slug='intro';"
# published 应该 true，comingSoon 应该 false

# 如果表是空的 → seed 没跑成功，重跑 pnpm db:seed:guide
```

---

### 🟡 12. 页面显示旧的（ISR 缓存没更新）

**原因**：ISR `revalidate = 600`（10 分钟缓存）

**解决**：
```bash
# 重启 pm2 会清缓存
pm2 restart <PM2_NAME> --update-env

# 或硬刷新浏览器：Cmd+Shift+R
```

## 部署成功验证清单

部署完成后，逐项检查：

```bash
SERVER=http://8.134.238.183   # 换成你的 IP 或域名

# 基础
curl -s -o /dev/null -w "%{http_code}" $SERVER/              # 应 200（跳转 /blog）
curl -s -o /dev/null -w "%{http_code}" $SERVER/blog           # 应 200
curl -s -o /dev/null -w "%{http_code}" $SERVER/agent-guide    # 应 200

# Agent 指南（前 3 篇打磨版）
curl -s -o /dev/null -w "%{http_code}" $SERVER/agent-guide/intro                    # 应 200
curl -s -o /dev/null -w "%{http_code}" $SERVER/agent-guide/phase-0-terminology      # 应 200
curl -s -o /dev/null -w "%{http_code}" $SERVER/agent-guide/phase-1-mindset          # 应 200

# WIP 章节应该 404（前端不可见）
curl -s -o /dev/null -w "%{http_code}" $SERVER/agent-guide/phase-2-python           # 应 404

# 首页应该有 Agent 指南卡片
curl -s $SERVER/blog | grep -o "Agent 指南\|guide-series-card" | head -1            # 应有输出

# admin 后台
curl -s -o /dev/null -w "%{http_code}" $SERVER/admin/guide    # 应 200（可能跳登录）
```
