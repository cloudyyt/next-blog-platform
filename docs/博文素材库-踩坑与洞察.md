## 素材 1：三重缓存诡异的 404（⭐⭐⭐⭐⭐ 强烈推荐）

**完整排查**：见 [`0726-admin-guide-静态预渲染大坑.md`](./0726-admin-guide-静态预渲染大坑.md)

### 核心冲突
线上 admin 列表页点编辑 → 404。但：
- 本地完全正常
- 服务器内 curl 真实 id → 200
- 浏览器直访真实 id → 能进
- 只有从列表页点编辑才 404

### 最抓眼球的点
**三重缓存叠加**：Nginx proxy_cache × Next.js ISR × Next.js 静态预渲染。每一层都返回旧数据，修一层没用，必须三层都清。

### 弯路价值（真实感）
6 个错误假设被逐一推翻：
1. 浏览器缓存 → 无痕也复现
2. 代码旧 → 本地构建上传，代码最新
3. Nginx 拦截 /admin → curl 200
4. Router Cache → 硬刷新无效
5. DB 两批 id → psql 查只有一批
6. Postico 连错库 → 确认连的对

**这种"我以为...结果..."的连环反转，是技术博文最吸引人的结构。**

### 深度点
`x-nextjs-cache: HIT` 这个 header **是 Next.js 产生的，被 Nginx 连同响应一起缓存了**——看起来是 Next.js 缓存，实际是 Nginx 缓存的旧 header。这个"header 也会被缓存"的认知，99% 的开发者没意识到。

### 读者痛点
所有用 Next.js + 宝塔/Nginx 反代的人都会踩。宝塔默认开 `proxy_cache`，本意给 PHP 加速，坑了 Node 应用。

### 建议标题
- 《一次诡异的 404：三重缓存如何让我排查到崩溃》
- 《Next.js 部署最大的坑：当 Nginx proxy_cache 遇上 ISR》
- 《为什么我的页面改了却不更新？三层缓存侦探故事》

## 素材 2：Node 18 vs 20 的隐藏地雷（⭐⭐⭐⭐）

**完整排查**：见 [`0725-oss-接入调研与接入草案.md`](./0725-oss-接入调研与接入草案.md) 踩坑记录

### 核心冲突
本地开发好好的，上传图片报 `ReferenceError: File is not defined`。

### 真相
Node 18 服务端 `File` 不是全局变量（在 buffer 模块里且实验性），Node 20+ 才设为全局。代码里 `instanceof File` 直接抛 ReferenceError。

### 抓人点
- **本地是 Node 18，服务器是 Node 20**——同一个 bug 本地必现、线上不现，反直觉
- 警告 `buffer.File is an experimental feature` 是线索，但容易忽略

### 读者痛点
Mac 默认 Node 版本可能旧，团队 Node 版本不统一是常态。

### 建议标题
- 《File is not defined：一个 Node 18/20 版本差异引发的血案》
- 《为什么我的代码本地崩、线上好？Node 版本地雷》

## 素材 3：Prisma migrate 的 drift 地狱（⭐⭐⭐⭐）

**完整排查**：见 [`0723-agent-guide-DB化与admin后台接线.md`](./0723-agent-guide-DB化与admin后台接线.md) 第五节

### 核心冲突
`prisma migrate deploy` 报 `P3018: relation "users" already exists`——表明明存在，它却要重建。

### 真相
早期用 `db push` 建表（不走迁移历史），后来想用 `migrate` 管理，但 DB 没有 `_prisma_migrations` 历史表，Prisma 以为所有迁移都没跑过。

### 抓人点
- `db push` 和 `migrate` 是两套体系，混用必坑
- `migrate resolve --applied` 是"骗"Prisma 的官方手段（只写历史不真跑）

### 读者痛点
所有从原型转向正经管理的 Prisma 项目都会遇到。

### 建议标题
- 《Prisma 迁移 drift：从 db push 到 migrate 的渡劫之路》
- 《P3018 报错自救：Prisma migrate 的 baseline 机制详解》

## 素材 4：rehype-raw 解析 SVG 的两个隐形地雷（⭐⭐⭐⭐）

**完整排查**：见 [`0725-oss-接入调研与接入草案.md`](./0725-oss-接入调研与接入草案.md) 「内联 SVG 渲染」节

### 核心冲突
markdown 里写 SVG，有的能渲染、有的被当代码块显示成乱码。

### 真相（两个坑）
1. **HTML 注释 `<!-- -->`**：rehype-raw 遇到 `-->` 提前结束 HTML 解析，后续缩进内容当代码块
2. **SVG 内部空行**：markdown 的 HTML block 规则——空行 = 块结束，导致 SVG 被腰斩

### 抓人点
- XML/SVG 完全合法，但放进 markdown 就崩——跨语法的解析冲突
- Node 单独测试 SVG 合法，但 react-markdown 全链路就腰斩——隔离测试 vs 集成测试的差异

### 读者痛点
所有想在 markdown 正文里嵌示意图的人（技术博主刚需）。

### 建议标题
- 《为什么我的 SVG 在 markdown 里被腰斩？rehype-raw 的两个隐形地雷》
- 《Markdown 内联 SVG 完全指南：避开 rehype-raw 的坑》

## 素材 5：ali-oss 的 proxy-agent 幽灵（⭐⭐⭐）

**完整排查**：见 [`0725-oss-接入调研与接入草案.md`](./0725-oss-接入调研与接入草案.md) 踩坑记录

### 核心冲突
接入阿里云 OSS，build 报 `Module not found: Can't resolve 'proxy-agent'`。

### 真相
ali-oss 依赖 urllib，urllib 里有动态 `require('proxy-agent')`。Next.js/Turbopack 打包时解析不到（该模块可选安装）。

### 抓人点
- **依赖的依赖的动态 require**——三层间接依赖，排查到这一层很考验耐心
- 解决方案是 `resolveAlias` 指向空模块——用"假的"骗过打包器

### 读者痛点
所有在 Next.js 里用 ali-oss/阿里云 SDK 的人。

### 建议标题
- 《Next.js + ali-oss：proxy-agent 幽灵依赖排查记》

## 素材 6：阿里云 ECS 访问国外源的连环坑（⭐⭐⭐）

**完整排查**：见 [`0726-部署上线与数据同步.md`](./0726-部署上线与数据同步.md) 「首次部署踩过的坑」

### 核心冲突
部署时连续踩：npm 源超时 → Prisma 引擎超时 → 还以为是代码问题。

### 真相
阿里云国内 ECS 访问 registry.npmjs.org / binaries.prisma.sh 普遍超时。要分别配 npmmirror（npm 包）+ PRISMA_ENGINES_MIRROR（Prisma 引擎）。

### 抓人点
- **两个独立的镜像源**，配了一个不够，另一个还要单独配
- 本地开发从不遇到（网络好），只有部署时才暴露

### 读者痛点
所有用阿里云/腾讯云国内节点部署 Node 应用的人。

### 建议标题
- 《阿里云 ECS 部署 Node 应用：那些国外源超时的坑》

## 素材 7：2C2G 服务器 build 卡死的生存指南（⭐⭐⭐）

**完整排查**：见 [`本地构建部署到服务器（不带node_modules）.md`](./本地构建部署到服务器（不带node_modules）.md)

### 核心冲突
服务器 `next build` 直接卡死（OOM），但本地 build 好的产物上传又有环境差异。

### 解决思路
本地 build → 打包 `.next` + 必要文件 → scp 上传 → 服务器只装生产依赖 + pm2 重启。

### 抓人点
- 个人开发者最常遇到的"服务器配置不够"现实
- 打包什么、不打包什么的权衡（node_modules 不带、docs 要带因为 seed 要用）

### 建议标题
- 《2C2G 服务器跑不动 next build？本地构建部署方案》

## 素材 8：Let's Encrypt 续签失败的两连坑（⭐⭐⭐）

**完整排查**：见本对话 2026-07-26 排查过程

### 核心冲突
证书续签失败，报"验证 URL 无法访问"和"DNS SERVFAIL"两个完全不同的错。

### 真相（两个独立坑）
1. **Next.js catch-all 路由拦截了 `/.well-known/`**：LE 验证文件被 Next.js 404，要在 Nginx 加 `^~` 强匹配
2. **根域 `@` 的 A 记录缺失**：LE 二级验证查根域，查不到 SERVFAIL

### 抓人点
- 一个续签失败，两个完全不同层面的根因（HTTP 路由 + DNS 记录）
- `^~` 前缀优先级 vs `location /` 的 Nginx 知识点

### 建议标题
- 《Let's Encrypt 续签失败的两种姿势：HTTP 拦截 + DNS 缺失》

## 如何使用这个素材库

### 写博文时
1. 挑一个素材，读对应的 07xx 文档拿完整技术细节
2. 用"核心冲突"作为开篇钩子
3. 用"弯路价值"展现真实排查过程（不要跳过错误假设，那是精华）
4. 用"深度点"做技术升华
5. 结尾点"读者痛点"扩大共鸣

### 素材之间的串联（适合写长文）
- 素材 1 + 7：都是部署相关的坑，可以写《Next.js 上线避坑指南》
- 素材 2 + 3 + 6：都是环境/工具链差异，可以写《本地能跑线上崩的 N 种原因》
- 素材 4 + 5：都是依赖/解析的间接问题，可以写《你不知道的依赖地狱》

### 持续积累
以后每次踩坑，按这个格式追加一条：
- 核心冲突（一句话讲清反直觉点）
- 真相（根因）
- 抓人点（为什么读者会看下去）
- 读者痛点（谁会遇到）
- 建议标题
- 完整技术细节指向哪个 07xx 文档
