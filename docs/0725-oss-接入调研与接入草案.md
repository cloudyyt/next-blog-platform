## 三、踩坑记录（按时间顺序，含解释）

### 坑 1：「资源包买了，但点 OSS 提示未开通」
- **现象**：买了 99 元资源包，进 OSS 控制台仍提示「您尚未开通对象存储服务 OSS」。
- **原因**：**资源包 ≠ 开通服务**。资源包是「预付费优惠券」，开通服务是「接通水管」。两个独立动作。
- **解决**：点提示里的「立即开通」，开通本身免费（¥0 走支付流程），开通后默认按量付费，资源包自动优先抵扣。

### 坑 2：「开通订单里捆绑了深度冷归档存储容量，删不掉」
- **现象**：开通确认订单页包含「对象存储 OSS」+「深度冷归档存储容量」两项，后者取消不了。
- **解释**：深度冷归档"容量"只是一个**空的计费容量池**，¥0 开通。只有当你**主动把数据存成"深度冷归档"类型**时才计费；建 Bucket 选标准存储，那个池子永远空着、永远 ¥0。
- **结论**：删不掉不管它，无影响。

### 坑 3：「Bucket 创建页一堆高级功能（资源组/版本控制/实时日志/HDFS 等）」
- **决策**：**全部保持默认/不开**。
  - 资源组保持 `default`（新建资源组会让 RAM 子账号权限配置变复杂，default 组所有子账号默认可见）
  - 实时日志查询（收费）、版本控制、归档直读、跨区域复制、HDFS —— 博客场景全部不需要
- **唯一必须手改**：读写权限从默认「私有」改成「**公共读**」（忘改的话图片加载不出来，事后也能在 Bucket 权限管理改）。

### 坑 4（待验证）：「RAM 子账号访问方式勾错」
- RAM 用户有两种访问方式：**控制台访问**（登录网页）vs **OpenAPI 调用**（用 AccessKey）。
- 我们只需要后者。**只勾「使用永久 AccessKey 访问 / Open API 调用」，不勾控制台访问**。
- 勾错会导致创建出来没有 AccessKey，得删号重建。

### 坑 5（待验证）：「权限策略给错范围」
- 阿里云默认的 `AliyunOSSFullAccess` 会授权操作账号下**所有** Bucket，过于宽泛。
- 本轮用**自定义策略**，`Resource` 字段锁定到 `blog-zijieleo-oss`，子账号只能动这一个桶。即使 AccessKey 泄露，损失局限在该桶。

| 变量 | 取值来源 | 备注 |
|------|---------|------|
| `OSS_REGION` | Bucket 所在地域，`oss-` + 区域名 | 华南3广州 = `oss-cn-guangzhou`（不带 https、不带 .com） |

| `OSS_ACCESS_KEY_SECRET` | RAM 子账号创建时显示 | 30 位字符串，**只显示一次**，丢失只能删号重建 |

> ⚠️ `.env` 已在 `.gitignore`，不会被提交。**Secret 切勿发聊天/截图/提交 git**。

### 6.2 存储层接口设计（关键：保证本地驱动可平滑切 OSS）

```
lib/storage/
  ├── types.ts        # StorageDriver 接口定义
  ├── oss.ts          # OSS 驱动（本轮主用）
  └── local.ts        # 本地驱动（public/uploads/，过渡/兜底用）
  └── index.ts        # 根据 env 选驱动
```

```ts
// lib/storage/types.ts
export interface StorageDriver {
  /** 上传文件，返回可访问的公网 URL */
  save(file: Buffer, key: string, contentType: string): Promise<string>;
  /** 删除文件（替换头像时删旧图） */
  remove(key: string): Promise<void>;
}

// lib/storage/index.ts —— 根据 env 自动选驱动
export function getStorage(): StorageDriver {
  if (process.env.OSS_USE_LOCAL === "true") return new LocalDriver();
  return new OSSDriver();
}
```

**OSS 驱动的 endpoint 切换**（本轮最重要的坑）：

```ts
// lib/storage/oss.ts
const isServer = process.env.OSS_USE_INTERNAL === "true"; // 服务器设 true
const region = process.env.OSS_REGION!; // oss-cn-guangzhou
const endpoint = isServer
  ? `https://${region}-internal.aliyuncs.com`  // 内网，免费
  : `https://${region}.aliyuncs.com`;            // 外网，本地 dev 用

export const ossClient = new OSS({
  region,
  accessKeyId: process.env.OSS_ACCESS_KEY_ID!,
  accessKeySecret: process.env.OSS_ACCESS_KEY_SECRET!,
  bucket: process.env.OSS_BUCKET!,
  endpoint,        // 显式指定 endpoint 覆盖 region 推导
  secure: true,
});
```

### 6.3 upload API（`app/api/admin/upload/route.ts`）

```
POST /api/admin/upload
  Content-Type: multipart/form-data
  body: { file: File, folder: "avatar" | "cover/post" | "cover/guide" | "content" }
  鉴权: verifyAdmin(request)
  处理:
    1. 校验类型（image/*）/ 大小（≤5MB）
    2. sharp 处理:
       - avatar:      resize 512x512 正方形 + 转 webp
       - cover/post:  resize width 1600 + 转 webp
       - cover/guide: 同上
       - content:     resize width 1200（正文插图不需那么宽，省流量）+ 转 webp

    3. key = `${folder}/${id}-${ts}.webp`（content 可保留原文件扩展名用于 GIF）
    4. storage.save(buffer, key, "image/webp")
    5. 返回 { url, key }
```

依赖追加：`pnpm add sharp`（无需 `@types/sharp`，自带类型）。

### 7.2 决策：独立单例表 `AuthorProfile`（✅ 2026-07-25 敲定）

- `SITE_PROFILE.author` 混了两类东西：「用户身份」（name、avatar）和「站点文案」（sidebarPromise、sidebarNote、显示用 role="记录者·全栈学习中"）
- `User.role` 是 **auth 角色**（"admin" / "user"），与显示文案 `author.role`（"记录者"）**不是一回事**，直接塞进 User 表会产生字段语义冲突（同名不同义）
- "博主是谁"在现有代码里靠 `findFirst({ role: "admin" })` 约定，但多 admin 时会歧义；且站点文案本质是**站点级配置**，不是用户身份
- 独立单例表与项目现有 `GuideSeriesConfig` 模式一致，认知统一

### 本轮（第二轮）踩坑记录
- **sharp 版本**：sharp 0.35 要求 Node ≥20.9.0，本地是 18.20.5 会导致本地 build 失败。降到 `0.33.5`（最后支持 Node 18 的版本）。**服务器是 Node 20.x，可正常使用 0.33.5**；将来本地升 Node 20 后可考虑升回 0.35。
- **pnpm 拦截 sharp 构建脚本**：pnpm 默认禁 sharp 的 install 脚本（安全策略）。在 `package.json` 加 `pnpm.onlyBuiltDependencies: ["sharp"]` 永久批准，否则 sharp 运行时加载会失败。
- **sharp 动态 import**：upload route 里 `import sharp` 会在 Next 收集 page data 阶段被加载，即使 route 是 `runtime: "nodejs"`，也可能在 edge runtime 收集时报错。改为 `const { default: sharp } = await import("sharp")` 延迟到运行时加载，彻底规避。
- **multipart 不要设 Content-Type**：`<ImageUploader>` / `<ContentImageUploadButton>` 用 `authFetch` 传 FormData 时，**不要**手动设 `Content-Type`，浏览器会自动加 `multipart/form-data; boundary=...`，手动设反而会破坏 boundary。`authFetch` 只补 `Authorization`，不影响。
- **ali-oss 必须标记为外部包**（`next.config.js`）：ali-oss 是 Node 原生 SDK，依赖的 `urllib` 里有动态 `require('proxy-agent')`，Next/Turbopack 打包时解析不到该模块会报 `Module not found: Can't resolve 'proxy-agent'`。解决：① `serverComponentsExternalPackages` 加 `'ali-oss'`（让 Next 不打包它，运行时从 node_modules 直接 require）；② Turbopack 兜底 `experimental.turbo.resolveAlias` 把 `proxy-agent` 指向 `scripts/empty-module.js` 空模块（仅走代理时才用到，本项目无 HTTP_PROXY，运行时不触发）。注意 Next 14 的 Turbopack 配置路径是 `experimental.turbo`，**不是**顶层 `turbopack`（顶层会报 "Unrecognized key"）。
- **不要用 `instanceof File` 校验上传文件**（Node 18 服务端坑）：Node 18 的 `File` 全局**不可见**（在 `buffer` 模块里且实验性，控制台会警告 `buffer.File is an experimental feature`），代码里写 `file instanceof File` 会抛 `ReferenceError: File is not defined`（因为裸 `File` 是 undefined）。Node 20+ 才把 `File`/`Blob` 设为全局。解决：用鸭子类型校验——`typeof file === "object" && typeof file.arrayBuffer === "function"`。这也兼容了 Undici/FileBlob 等各种实现，比 `instanceof` 更稳。

### 内联 SVG 渲染（Agent 指南正文插图）
为支持正文里放 SVG banner 图（Stripe/Linear 风格技术示意图），启用 react-markdown 的内联 HTML 渲染：

- **装依赖**：`rehype-raw`（解析 markdown 里混写的原始 HTML/SVG）。`rehype-sanitize` **不可用**——它默认 schema 不处理 SVG 命名空间（foreign namespace），即使把 svg/rect/text 加进 tagNames，也会把整个 `<svg>` 当非法元素删掉，只剩子元素文字残骸。
- **配置**（`components/blog/post-content.tsx`）：`rehypePlugins: [rehypeRaw]` + 在 `components` 里把 SVG 标签白名单透传为对应小写元素（见 `lib/markdown/rehype-schema.ts` 的 `ALLOWED_SVG_TAGS`）。XSS 防护靠标签级白名单（PostContent 只渲染博主内容，admin 鉴权后写入 DB，非用户输入，风险低）。
- **SVG 硬性规则（必须遵守，否则渲染会坏）**：
  - ❌ 不能有 HTML 注释 `<!-- -->`（rehype-raw 遇到 `-->` 会提前结束 HTML 解析，后续缩进内容被当 markdown 代码块）
  - ❌ SVG 标签之间不能有空行（markdown 的 HTML block 规则：空行 = HTML block 结束，会导致 SVG 被腰斩，只渲染前半段）
  - ✅ 整个 `<figure>...</figure>` 必须是**连续无空行**的块（元素间可有缩进，但不能有空行）
  - ✅ 用 `<figure><svg>...</svg><figcaption>图注</figcaption></figure>` 包裹
- **react-markdown v9 的 `inline` 参数废弃**：`code` 组件里不能用 `if (!inline)` 判断行内/块级代码（v9 起 inline 永远 undefined），会导致行内代码（反引号）被误判为块级 → 走 SyntaxHighlighter 返回 `<div>` → 嵌进 `<p>` → hydration error（`<div>` 不能是 `<p>` 后代）+ 行内代码失去样式。改用内容特征判断：`const isBlock = match !== null || text.includes("\n")`。
- **dev 热重载失效**（iCloud 路径）：项目在 `~/Library/Mobile Documents/...` iCloud 路径下，Turbopack 文件监听对这种路径经常失效，改 PostContent 后 dev 可能不重新编译。现象：Node 端测试 SVG 渲染正常，但浏览器看到的还是旧的。解决：彻底杀掉所有 next 进程 + 删 `.next` + 重起 dev。

## 九、RAM 权限策略 JSON（存档，便于将来换号/加桶时复用）

`BlogOSSUploaderPolicy` 自定义策略（脚本编辑模式，照抄）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:GetObject",
        "oss:DeleteObject",
        "oss:ListObjects",
        "oss:AbortMultipartUpload",
        "oss:ListParts",
        "oss:HeadObject"
      ],
      "Resource": [
        "acs:oss:*:*:blog-zijieleo-oss",
        "acs:oss:*:*:blog-zijieleo-oss/*"
      ]
    },
    {
      "Effect": "Allow",
      "Action": [
        "oss:GetService",
        "oss:ListBuckets"
      ],
      "Resource": "*"
    }
  ]
}
```

**Action 说明**：PutObject(上传) / GetObject(读取) / DeleteObject(删旧图) / ListObjects(admin 列图) / AbortMultipartUpload+ListParts+HeadObject(SDK 内部机制) / GetService+ListBuckets(SDK 初始化探测)。

**安全要点**：`Resource` 锁定到 `blog-zijieleo-oss`，子账号只能动这一个桶；即使 AccessKey 泄露，损失局限在该桶。
