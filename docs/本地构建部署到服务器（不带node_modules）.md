# 本地构建部署到服务器（不带 node_modules）

适用场景：服务器配置较小（例如 2C2G），服务器上 `next build` 经常崩；改为**本地构建**，服务器只做**解压覆盖 + 安装生产依赖 + pm2 重启**。

> 说明：本流程**不打包 `node_modules`**，因此服务器仍需要执行一次 `pnpm install --prod`。

---

## 你需要先确认/替换的变量

- **服务器 IP**：`<SERVER_IP>`
- **服务器项目目录**：`<SERVER_DIR>`
  - 例：`/www/wwwroot/next-blog-platform`
- **pm2 进程名**：`<PM2_NAME>`
  - 例：`blog`

---

## 1）本地（Node 20）构建 + 打包

在项目根目录执行：

```bash
pnpm install
pnpm run build
tar -czf release.tgz .next package.json pnpm-lock.yaml prisma
```

如果你项目没有 `prisma/`（一般都有），就去掉：

```bash
tar -czf release.tgz .next package.json pnpm-lock.yaml
```

---

## 2）上传到服务器指定目录

```bash
scp release.tgz root@<SERVER_IP>:<SERVER_DIR>/
```

---

## 3）服务器：解压覆盖 + 安装生产依赖 + 重启

登录服务器后执行：

```bash
cd <SERVER_DIR>
tar -xzf release.tgz
pnpm install --prod --frozen-lockfile
pm2 restart <PM2_NAME> --update-env
--- pm2 restart blog --update-env
```

> 如果你服务器上依赖源有问题（例如 npmmirror 404），建议先切到官方源：
>
> ```bash
> pnpm config set registry https://registry.npmjs.org/
> ```

---

## 4）常见问题排查

### A. 服务器 `next start` 报环境变量/数据库连接问题

- 确认服务器目录下 `.env` 存在且配置正确（尤其是 `PRISMA_DATABASE_URL`、`JWT_SECRET`、`NEXT_PUBLIC_BASE_URL`）。
- 重启用 `pm2 restart <PM2_NAME> --update-env`，确保 pm2 读到最新环境变量。

### B. 服务器 `pnpm install --prod` 还是崩

这是服务器资源瓶颈导致的。可以临时用更低并发/更小内存的方式跑安装，或者改用“带 node_modules 的打包方案”。
