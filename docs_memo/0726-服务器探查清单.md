# 服务器探查清单（部署前必做）

> 你 ssh 上服务器后，按本文逐条执行，查清楚所有部署需要的信息。
> 查完后回来告诉我结果，我帮你配 .env。

---

## 第 1 步：ssh 上服务器

```bash
ssh root@8.134.238.183
# 输入改过的新密码
```

---

## 第 2 步：查项目目录在哪

```bash
# 宝塔通常在 /www/wwwroot/ 下
ls /www/wwwroot/
# 找到你的博客项目目录，比如 /www/wwwroot/next-blog-platform

# 确认是项目目录（应该有 package.json / .next / prisma 等）
ls /www/wwwroot/<你的项目目录>/
```

👉 **把项目目录路径告诉我**（例如 `/www/wwwroot/next-blog-platform`）

---

## 第 3 步：查 pm2 进程名

```bash
pm2 list
```

输出会是一个表格，找 `name` 列里你的博客进程名（比如 `blog` / `next-blog` 等）。

👉 **把 pm2 进程名告诉我**

---

## 第 4 步：查现有 .env（关键！）

```bash
# 进项目目录
cd /www/wwwroot/<你的项目目录>

# 看 .env 内容（注意：含敏感信息，看完不要截图发我，口头描述有哪些变量即可）
cat .env
```

👉 **告诉我这个 .env 里有哪些变量**（不用发值，只说变量名）：
- 有没有 `PRISMA_DATABASE_URL`？值里 host 是什么（127.0.0.1？还是别的）？端口是几？
- 有没有 `DATABASE_URL`？
- 有没有 `JWT_SECRET`？
- 有没有 `NEXT_PUBLIC_BASE_URL`？
- 有没有 `IP_HASH_SALT`？
- 有没有 `OSS_*` 相关的？（应该没有，这是本次新增的）

**重要**：这个 .env 是你线上博客正在用的，**DB 连接信息是对的**（博客能跑就说明连得上）。我们等会只需要**追加 OSS 变量**，不要动现有的 DB 配置。

---

## 第 5 步：确认 postgres 在跑

```bash
# 宝塔通常用 Docker 跑 postgres
docker ps | grep -i postgres
# 会看到类似：xxx/postgres:14  0.0.0.0:5432->5432/tcp

# 记下端口映射（5432->5432 说明端口是 5432）
```

如果不是 Docker：
```bash
systemctl status postgresql
# 或
psql --version
```

👉 **告诉我 postgres 的端口**（一般是 5432，但宝塔可能改过）

---

## 第 6 步：查 Node 版本

```bash
node -v
```

👉 **告诉我版本号**（需要 ≥ 20，否则 sharp 会有问题）

如果低于 20：
```bash
# 用 nvm 升级
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install 20
nvm use 20
node -v   # 确认是 v20.x
```

---

## 第 7 步：查 pnpm

```bash
pnpm -v
```

如果 `command not found`：
```bash
npm install -g pnpm
```

---

## 第 8 步：测试 OSS 内网连通性（可选，但建议）

```bash
# 服务器走内网访问 OSS，确认能通
curl -o /dev/null -s -w "%{http_code}" \
  https://blog-zijieleo-oss.oss-cn-guangzhou-internal.aliyuncs.com/
# 返回 403 或 200 都说明内网能通（403 是因为没带认证，但说明网络通）
# 如果超时 → 内网不通，OSS_USE_INTERNAL 不能设 true
```

---

## 你查完后，把这些信息告诉我

```
项目目录：       /www/wwwroot/xxx
pm2 进程名：     xxx
Node 版本：      v?.?.
pnpm 版本：      ?.?.?
postgres 端口：  5432 或其他
现有 .env 变量： [PRISMA_DATABASE_URL, JWT_SECRET, NEXT_PUBLIC_BASE_URL, ...]
OSS 内网测试：   通 / 不通
```

**拿到这些信息后，我帮你**：
1. 生成完整的 `deploy.config.sh`（你复制粘贴即可）
2. 列出服务器 .env 需要**追加的 OSS 变量**（不动现有的 DB 配置）
3. 确认一切就绪后，你再跑 `deploy.local.sh`
